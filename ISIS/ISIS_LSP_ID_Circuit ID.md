# IS-IS LSP-ID & Circuit ID – Architect Notes + Interview  

  

## 1. LSP-ID (Identification of LSP)  

  

- What: Unique identifier for each LSP; represents the originating router and specific LSP instance.  

- Why: Required to uniquely track and manage LSPs in LSDB across entire IS-IS domain.  

- How:  

LSP-ID = **System ID + Pseudonode ID + LSP Fragment Number**  

  

- System ID → identifies router (6 bytes)  

- Pseudonode ID → identifies DIS-generated pseudonode (or 00 for normal router)  

- LSP Number → identifies fragment number  

  

- Risk:  

- Misunderstanding LSP-ID → incorrect troubleshooting of LSDB  

- Fragmentation can increase LSDB complexity  

- Example:  

- Large topology → multiple LSP fragments → harder to track routing issues  

- Takeaway:  

LSP-ID uniquely identifies every piece of topology information in IS-IS.  

  

👉 Interview Angle:  

LSP-ID uniquely identifies LSPs and includes router identity, pseudonode reference, and fragment number.  

  

---  

  

## 2. LSP-ID Formats (Key Understanding)  

  

### 🔷 Regular LSP

R1-00.00

```
- System ID = R1  
- Pseudonode ID = 00  
- Fragment = 00  

✅ Meaning:
- Normal LSP generated by router

---

### 🔷 Fragmented LSP
```

R1-00.02

```
- Fragment number > 00  

✅ Why:
- LSP size exceeds MTU → broken into fragments

✅ Risk:
- More fragments → more LSDB entries → higher SPF load

---

### 🔷 Pseudonode LSP
```

R1-01.00

```
- Pseudonode ID ≠ 00  

✅ Meaning:
- Generated by DIS representing LAN

✅ Design Insight:
- Each broadcast LAN creates pseudonode LSP

---

## 3. Pseudonode ID (Important Behavior)

- What:
  - Identifies pseudonode created by DIS
- Why:
  - Needed to represent multi-access network as single node
- How:
  - Non-zero value assigned per LAN
- Risk:
  - Multiple LANs → multiple pseudonodes → LSDB growth
- Example:
  - Large VLAN environment → many pseudonode LSPs

- Takeaway:
  Pseudonode simplifies topology but increases dependency on DIS

---

## 4. Circuit ID (Adjacency Identification)

- What:
  - Identifies interface/adjacency in IS-IS Hello packets

---

### 🔷 Broadcast Network
- Contains:
  - DIS System ID
  - Non-zero circuit number

✅ Why:
- Needed to distinguish multiple interfaces on same router

---

### 🔷 Point-to-Point Network
- Contains:
  - Non-zero identifier for neighbor relationship

✅ Simpler vs broadcast (no DIS involvement)

---

## 5. Why LSP-ID Structure Matters (Design Thinking)

- System ID → Router identity  
- Pseudonode ID → LAN representation  
- Fragment → Scalability handling  

👉 Together they enable:
- Unique LSDB entries
- Efficient flooding
- Scalable topology representation  

---

## 6. Real-World Scenario (STAR Applied)

- S:
  Network troubleshooting showed multiple unexpected LSP entries, causing confusion in LSDB analysis.

- T:
  Identify reason for multiple LSPs per router.

- A:
  Analyzed LSP-ID structure and identified fragmented LSPs due to large topology and MTU constraints.

- R:
  Optimized design by reducing unnecessary prefixes and improving summarization; LSDB became cleaner and easier to manage.

Short Explanation:
Multiple LSP fragments are normal in large networks but must be understood during troubleshooting.

- Final Line:
Understanding LSP-ID structure is essential for diagnosing LSDB issues and scaling IS-IS networks effectively.

---

## 7. Quick Recall (Interview)

- LSP-ID = System ID + Pseudonode ID + Fragment  
- 00 pseudonode → normal router LSP  
- Non-zero pseudonode → DIS (LAN)  
- Fragment > 00 → large LSP  

- Circuit ID:
  - Broadcast → DIS + number  
  - P2P → simple identifier  

---

## 8. Final Architect Insight

LSP-ID is the foundation of IS-IS database structure.  
It not only identifies routers but also represents LAN abstraction (pseudonodes) and scalability mechanisms (fragmentation).  
A deep understanding of LSP-ID helps in effective troubleshooting, scaling, and design optimization.
```
